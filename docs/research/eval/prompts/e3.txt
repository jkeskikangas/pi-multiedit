Implement this change in the repository:

Label support Slack alerts and ping the channel without personal data

Support alerts (new-work, unclaimed-work and response-due notifications) now include one Slack channel broadcast mention and a fixed deployment label, so the message text becomes `[<label>] <!channel> <existing template text> <queue link>`, with the Finnish templates and the "Avaa asiakaspalvelun työjono" link text unchanged.

- The customer-service notification config struct gains an `environment_label` field. It is derived from the environment passed to `parse/3`, never from the raw config map: `prod`/`production` -> "prod", `prerelease` -> "prerelease", `staging` -> "staging", `dev`/`development` -> "dev", `test` -> "test" (atoms or strings). Any other environment fails configuration validation (`{:error, :configuration_needed}`).
- `load/0` uses the `:deployment_env` app setting when present, falling back to `:app_env`, so prerelease (which runs the production app profile) cannot mislabel alerts as prod.
- The queue-URL origin check uses the normalized label.
- Messages contain only the static environment label, the mention, the fixed event text and the generic staff-queue link.
